系统架构与数据流

课堂展示主视图：先讲机制，再进行右侧 live demo

普通 RAG 的核心是 Retrieve → Generate。CiteTrace 进一步加入独立检索、claim 级证据核查和 disagreement-aware abstention。

1 · User Question

科研论文事实性问题，例如数据规模、训练模态、实验设置、消融结果。

2A · Qwen Retriever

独立生成检索 query，寻找支持问题的原文证据。

2B · DeepSeek Retriever

从另一模型路径独立检索，降低 query formulation 导致的 evidence miss。

3 · Evidence Pool

合并、去重并保留 page / section / source，实现可追溯证据池。

4 · Answer Agent

只基于 Evidence Pool 回答，同时生成可独立检查的 atomic factual claims。

5 · Atomic Claims

把复合答案拆成多个最小事实陈述，避免“整段 citation”掩盖局部错误。

6A · DeepSeek Verifier

独立判断 claim 与 evidence 的支持关系。

6B · GLM Verifier

不看另一个 verifier 的结果，减少 anchoring。

7 · Agreement / Conflict

SUPPORTED / PARTIAL / UNSUPPORTED / UNKNOWN。冲突本身作为风险信号。

8 · Final Output

回答 + 原文证据 + verifier 判定；必要时主动 abstain。

课堂一句话： CiteTrace 不是“多模型投票回答”，而是把不同模型放在证据检索和 claim-evidence verification 两个独立环节，用模型间 disagreement 暴露单模型可能漏掉的错误。
